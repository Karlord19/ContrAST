\chapter*{Introduction}
\addcontentsline{toc}{chapter}{Introduction}

In order to learn programming, it is necessary to write a lot of code.
It is of no use to copy code written by someone else, even if it is correct and solves the problem.
Students are often aware of this fact, but they still sometimes copy from others; and the teachers need appropriate tools to detect such cases of plagiarism.

We will focus on the current situation at the Faculty of Mathematics and Physics at the Charles University, where the assignments and exams for introductory programming courses are submitted in the form of source code files to an online system called Recodex.
Teachers configure a set of test cases for each assignment, and the system automatically runs those tests to check the correctness of the submitted programs.

Recodex provides a plagiarism-detection tool called Comparatrix.
It is based on a string representation of the source code, only removing comments and whitespace.
All substrings of the code are stored in a database, and the tool can quickly find identical segments of code between different submissions.
This approach has a few disadvantages primarily because the full lexical and semantic analysis is not performed.
The fragments do not correspond to syntactical structures and the tool only detects identical code.
Slightly modified code, for example with renamed identifiers, will not be detected at all.

To address these issues, we need to perform at least some level of syntactic (and possibly semantic) analysis of the code, then store the resulting structures efficiently in a database, and finally search for structurally similar code fragments.
This naturally leads us to Abstract Syntax Trees (ASTs) as the main data structure for representing the code, and a measure of code similarity applicable to labeled trees.

Languages primarily used in Recodex are Python, C\#, and C++.
There already is a syntax-driven tool for detecting plagiarism in Recodex focused on Python submissions \cite{saksa20}.
We did not use it as a basis for our work, as we wanted another implementation for storage and add a similarity measure.
We then targeted C++, its our favorite language.
The core of our tool shall be language-agnostic, and to add support for other languages, we only need to implement the parsing, AST construction, and a short configuration for those languages.

Some C++ parsers are available and would be absolutely sufficient for our purposes.
However, another diploma thesis is currently being written at our department, which needs a full semantic analysis of the code, and thus a more complex parser.
Its purpose is to provide a recommender system for teaching assistants, which will suggest feedback for students based on the code they submitted.

We decided to use clang/LLVM as the parser for C++ code (and also for C and arduino code), as it provides a full syntactic and semantic analysis, is well-maintained, and is easy to use as a library.
As part of a research project preceding this thesis, we have already implemented a tool called atc (short for AST to comparatree) that extracts ASTs from C++ code using clang and stores them in a database.
The database is called comparatree, maintained by the supervisor RnDr. David Bednárek Ph.D., and is designed to very efficiently store ASTs.
The main contribution of this thesis is a tool called ContrAST, which implements a similarity measure for ASTs and creates reports of similar code fragments, that can be imported into Recodex.
Recodex will then use these reports to show the teachers which submissions are similar and which code fragments they have in common.
