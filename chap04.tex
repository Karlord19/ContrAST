\chapter{\texttt{atc}}\label{sec:atc}

\texttt{atc} \cite{atc} is a C++ tool for parsing C/C++ code into \texttt{comparatree}. It was primarily developed as part of a research project preceding this thesis, and later slightly changed to fulfill new interface requirements of \texttt{comparatree} and the whole project.
See the documentation of \texttt{atc} in the research project for more details.

\texttt{atc} is also used in another diploma thesis that needs semantic information from the code.
This led to choosing the LibTooling library \cite{libtooling} from Clang, which lets us create a standalone tool for parsing C++ code and extracting the relevant information from the ASTs.

The main structure of \texttt{atc} is standard for a Clang-based tool.
We define a class \verb|AtcConsumer| that inherits from \verb|ASTConsumer|, which accepts a translation unit and processes it.
The processing is done by a class \verb|AtcVisitor| that inherits from \verb|RecursiveASTVisitor|, which provides a convenient way to traverse the abstract syntax tree (AST) generated by Clang and visit each node.
We only need to override the concrete visit methods for the AST nodes that we want to capture in \texttt{comparatree}, collect the interesting information from the AST nodes, and build the corresponding \texttt{comparatree} structures.

The \verb|RecursiveASTVisitor| class provides different traversal approaches, see \autoref{fig:atc-recursive-visitor}.
We will refer only to the postorder traversal, which we prefer for \texttt{comparatree}.
\begin{itemize}
\item The \verb|Traverse*| methods are called for each AST node automatically, as they call traversal methods for all the children of the node, and then call the corresponding \verb|WalkUpFrom*| method for the node itself.
\item The \verb|WalkUpFrom*| methods call a \verb|WalkUpFrom*| method for a superclass of the node, and then call the corresponding \verb|Visit*| method for the node itself.
\item The \verb|Visit*| methods are empty.
\end{itemize}

The user can override any of the methods.
We choose to leave the \verb|Traverse*| methods unchanged, as they provide the desired traversal order and behavior.
We override the \verb|WalkUpFrom*| methods to capture the needed information from the AST nodes, and we do not include the calls to the superclass methods and the calls to the \verb|Visit*| methods.
This leads to visiting each node only once.
If we do not override a specific \verb|WalkUpFrom*| method, it automatically calls the superclass method, and then its superclass method, and so on, until it reaches a \verb|WalkUpFrom*| method that we did override where we can collect at least some information from the node.
We call it a fallback when we do not visit the node directly, but through its superclass.

We can also use the hierarchy of the classes of AST nodes for extracting different levels of information about the node.
Each class adds some specific information on top of the information captured by its superclasses.
We capture the specific information of each class and call the superclass extraction method to capture the full information about the node.

We also build the type descriptors according to the type hierarchy of the AST node classes.

\section{Statistics}

The statistics were primarily collected during the research project, as the results directly influenced the design of the tool and the choice of the AST nodes to capture.

We collected about 24K submissions from ReCodEx in introductory and advanced C++ courses on July 24, 2025, containing about 43K source files.
The data was anonymized and is not publicly available.

\begin{figure}[ht]
  \centering
  \includegraphics[width=\textwidth]{img/atc-node-labels.eps}
  \caption{Occurrences of different AST node labels. The node labels are on the x-axis, on the y-axis is the percentage of files where they occur at least once. The line separates the node labels that we capture in \texttt{comparatree} from those that we do not capture. From 150 collected node labels, we capture about 80.}
  \label{fig:atc-node-labels}
\end{figure}

The Clang AST contains a lot of different node types, and we are not able to capture all of them.
\autoref{fig:atc-node-labels} shows the occurrences of different node labels in the dataset.
We set 9 percent as a threshold for capturing the node labels in \texttt{comparatree}, which means that we capture all node labels that occur in at least 9 percent of the files.
This was set as a required minimum, but we also captured about 20 node labels that correspond to important superclasses, as we can still collect the most significant information about the node through a fallback.

We then counted the fallbacks, as it measures the quality of the resulting ASTs.
From 27M processed Clang AST nodes, we had 127K fallbacks, which is about 0.5 percent of the nodes.

When a node is captured through a fallback, it might not contain all the information that we could capture if we visited the node directly.
Specifically, we might not find all of the node's children.
Those child nodes are traversed by the framework but are not connected to the parent node, and thus are not present in the resulting module in \texttt{comparatree}.

We call nodes that do not belong to any module in \texttt{comparatree} \emph{off-tree nodes}, as they were forgotten during the use of fallbacks.
From 108M nodes in the resulting \texttt{comparatree}, we had 845K off-tree nodes, which is about 0.8 percent of the nodes.
Note that we refer to the number of nodes we created in \texttt{comparatree}, not the number of nodes in the Clang AST.
The tool creates intermediate nodes in \texttt{comparatree} that do not have a direct counterpart in the Clang AST, and thus the number of nodes in \texttt{comparatree} is not the same as the number of nodes in the Clang AST.

The time to process a file by \texttt{atc} is 0.9 seconds on average, of which only 0.9 percent is spent in our code, and the rest is spent in Clang for generating the AST.
